# SWitch 진행 상태

2026-11-19 대화 기준입니다. 아래 제품 방향은 계획이며, 현재 구현된 하드웨어 테스트와 구분합니다.

## 제품 방향

- 시니어의 키오스크 이용을 돕는 대화형 음성 주문 에이전트.
- 기존 키오스크를 유지하고 음성 수집 모듈 및 소프트웨어를 추가하는 방향.
- 화면을 읽고 클릭·스크롤 등으로 기존 주문 UI를 조작하는 방식 검토.
- 자연스러운 대화로 메뉴·수량·옵션을 점차 확정하고, 수정·취소 및 결제 화면 진입을 지원하는 것을 목표로 함.
- 반복 실패 시 주문 맥락을 유지해 직원에게 인계하는 UX를 계획.
- 비용 지불 고객은 매장 운영자·프랜차이즈 본사 등이며, 최종 사용자인 시니어와 구분.
- 초기 시장은 프랜차이즈 매장, 병원·공공기관·민원 키오스크 등은 후속 확장 시장으로 구분한 상태. 후속 시장에는 주문과 다른 업무 흐름이 필요함.
- 초기 실험 대상으로 Windows 기반 토스 키오스크를 희망했으나, 실제 연동·제휴·상용 운영 가능성은 검증된 것으로 취급하지 않음.

## 현재 구현된 하드웨어 테스트

- ESP32-S3 SuperMini + ICS-43434 + 푸시버튼 + 별도 LED.
- 스피커는 PC 출력 사용. ESP32에 직접 스피커를 연결하는 기능은 구현하지 않음.
- 마이크 I2S 입력을 48kHz·모노·16비트 PCM으로 변환해 USB 시리얼로 전송.
- PC Python 프로그램에서 CRC 검증 후 오디오 출력 장치로 재생.
- 버튼/LED 테스트, 버튼을 누를 때만 재생, 버튼과 무관한 상시 재생 모드 제공.
- DC 성분 제거, 60ms 사전 버퍼, 5ms 전환 페이드, 전송·재생 오류 진단 수치 추가.
- 서버 전송·음성인식·주문 대화·화면 조작은 이 테스트 코드에 포함되지 않음.

## 배선

| 부품 | 단자 | ESP32 연결 |
| --- | --- | --- |
| ICS-43434 | 3V | 3V3 |
| ICS-43434 | GND | GND |
| ICS-43434 | SEL | GND: 왼쪽 채널 |
| ICS-43434 | BCLK | GPIO4 |
| ICS-43434 | LRCL | GPIO5 |
| ICS-43434 | DOUT | GPIO6 |
| 버튼 | 평상시 분리된 두 접점 | GPIO7과 GND |
| 일반 LED | + | GPIO8 → 330Ω 저항 → LED + |
| 일반 LED | - | GND |

보드 설정과 자세한 주의사항은 각 하드웨어 폴더의 README를 따릅니다.

## 실제 확인한 사항과 남은 문제

- ESP32 오디오 전송 스케치 컴파일 성공.
- PC 프로그램이 연결된 ESP32와 오디오 출력 장치를 인식함.
- 작은 997Hz 테스트음을 Mac 내장 스피커로 재생했을 때 ESP32 입력에서 해당 주파수 성분이 증가함을 확인.
- 원본 입력에서 매우 낮은 주파수 성분이 크게 관찰됨. 이것만으로 특정 부품·배선 문제를 확정하지 않음.
- PC 필터 적용 후 사용자가 “말소리가 들리고 팝 소리도 줄었다”고 확인함.
- 4배 증폭에서 클리핑이 발생해 상시 듣기 실행 파일은 2배로 설정함.
- 2배 설정의 초기 약 20초 관찰에서는 진단 오류가 0이었지만, 이후 장시간 실행 로그에는 일부 패킷 누락·오래된 버퍼 데이터 폐기·클리핑이 발생함. 완전히 해결되었다고 판단하지 않음.
- 오디오 디코더·재생 버퍼·필터 자동 테스트 14개 통과.
- 마지막 사용자 요청에 따라 재생 프로그램을 종료했으며, 이번 파일 정리 작업에서 음성 재생을 다시 시작하지 않음.

다음 음질 점검에서는 사용자의 거리·발화 조건을 고정하고 `gaps`, `bad`, `starve`, `out_underflow`, `dropped`, `clip`의 증가 여부를 함께 확인합니다. 실제 키오스크 연동은 별도 검증 과제입니다.

## 키오스크 UI 개발 추가

- 사용자 제작 본체: J3710 / DDR3 8GB 미니 PC, Windows 11, 16인치 16:10 WQHD 터치모니터, Epson TM-m30. 사용자 확정: 80mm 용지, USB 연결.
- 우선 Mac 로컬 개발 환경에서 React + TypeScript + Vite 웹 앱으로 UI와 주문 흐름을 검증. 최종 Windows 실행 파일은 Tauri 2로 구성하는 방향이며 아직 패키징하지 않음.
- 디자인 기준: Figma `창캡디`, Frame 121 (`55:2`), 세로형 1600×2560.
- 사용자 승인한 `kiosk-web/public/assets/figma` 경로에 데스크톱 MCP 서버를 통해 원본 이미지·SVG 확보. 원본 디자인 문서는 수정하지 않음.
- 메뉴 화면 하단에 주문 내역 표시. 옵션 수정·수량 조절·삭제와 목록 스크롤 및 위/아래 버튼 제공.
- 사용자 수정 사항: `전체보기` 제거, 하단 `결제하기` → 주문 전체 확인 → `확인하고 결제하기` → 결제수단 선택. 확인 화면에 큰 `이전으로` 버튼 제공.
- 매장·포장 선택, 필수 옵션 검사, 품절, 모의 결제 성공·실패·취소·응답 없음, 임시 주문 복원, 주문 저장·조회·주문번호 발급, 유휴/완료 후 초기화 구현.
- 실제 결제·프린터·음성 대화·화면 조작 에이전트는 아직 연결하지 않음. 앱 실행과 수정 방법은 `kiosk-web/README.md` 참조.

## 영수증 구현 추가

- 상세 영수증과 픽업 주문서 2종: 80mm 용지·72mm 내용 폭, 흑백, 큰 주문번호, 메뉴·수량·옵션. 상세 영수증에는 합계 및 체험 결제수단 표시.
- 개발 도구의 `영수증 시안`과 완료 화면의 `영수증 보기`, 주문 이력에서 확인 및 OS 인쇄 창으로 전달 가능.
- 주문 당시 메뉴명·단가·옵션을 보존해 재조회 시 변경 방지. 디자인 시안은 실제 주문 이력과 분리.
- 인쇄 창·PDF 저장까지 웹 경로를 구현했으며 실제 USB 연결·용지 출력·자동 절단·네이티브 상태 조회는 미검증. Tauri 2 프린트 브리지와 구분.
- `output/pdf/`에 실제 크기 PDF 시안, `kiosk-web/qa/`에 화면 및 검증 결과 보관.
- 후속 요청 반영: 영수증의 디자인 샘플/데모/체험 문구 제거. 웹 `프린터 설정`에서 자동 출력·출력 종류 저장, 결제 완료 후 주문 ID별 1회 자동 인쇄 요청. 실패·취소·이력 조회에는 자동 출력하지 않음.
- 인쇄 창 없는 Windows 데모 실행용 `.cmd` 다운로드 제공. 별도 Chrome 프로필을 공유하는 최초 설정 모드와 `--kiosk-printing` 실행 모드로 구성. 웹만으로 프린터 열거/선택·무인 인쇄가 되는 것으로 표현하지 않으며, 실제 Windows/USB 출력은 사용자 장비 검증 필요. 최종 Tauri 2 패키징 방향은 유지.
