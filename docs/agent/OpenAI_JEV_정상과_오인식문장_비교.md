# OpenAI·JEV 정상/오인식 문장 비교

2026-11-22, sdylab에서 실제 API 호출. 정상 24개 + 가정 STT 오인식 24개를 각 모델에 1회씩 보내 총 96회 판정했다.

모델: OpenAI `gpt-5.6-luna`, JEV `jev-latest`. JEV는 두 Choice 질문과 기존 확률·confidence 문턱을 조합한 현재 어댑터의 결과다.

## 조건

- 두 모델에 같은 문장·같은 문맥을 입력. 정상 짝 문장과 정답은 모델에 보내지 않았다.
- STT·마이크 성능 시험이 아니라 STT 뒤 의미 필터의 회귀 시험이다. 오인식 문장은 수작업으로 가정했다.
- Python 단답·직접 주문 빠른 판별을 두 모델 모두 끔. 모델별 호출 순서를 번갈아 측정.
- 타임아웃 4초, 자동 재시도 0회. 성공 응답의 왕복시간에 첫 TLS 연결 시간도 포함.
- 작은 수기 정책 정답셋 1회 결과다. 현장 정확도나 통계적으로 확정된 우열로 일반화할 수 없다.

|---|---:|---:|

## JEV 결과를 해석할 때 주의할 점

실패 사례 일부를 추가 API 호출로 조사했더니 JEV 자체의 최상위 선택과 현재 Python 어댑터의 최종 결과가 달랐다. 아래는 본 시험과 별도로 다시 호출한 진단 결과이며, 같은 문장도 confidence가 달라질 수 있다.

| 문장 유형 | JEV 최상위 선택 | 해당 확률 | confidence | 어댑터 결과 |
|---|---|---:|---:|---|
| wallet:clean | other | 0.91 | 0.86 | 전달 |
| broadcast:clean | other | 0.92 | 0.88 | 전달 |
| announcement:clean | other | 0.83 | 0.74 | 전달 |
| and:clean | uncertain | 0.83 | 0.74 | 전달 |

기존 정책은 `other`여도 확률과 confidence 중 작은 값이 0.90 이상일 때만 무시한다. 예를 들어 방송으로 0.92, confidence 0.88이면 코드가 전달로 바꾼다. 대상이 uncertain이면 미완료 판정보다 원문 전달을 우선하는 정책도 있다. 따라서 위 JEV 정답률은 모델 능력만의 수치가 아니다. 문턱을 평가셋에 맞춰 조정한 뒤 동일 자료로 개선됐다고 주장하지 않았다. 정책 조정은 별도 검증셋과 손님 말 오차단율을 함께 확인해야 한다.

## 키 설정과 재실행

키는 sdylab `/home/sdy/.config/switch-agent/agent.env`의 `TYPESAFE_API_KEY`다. 값은 소스나 보고서에 보관하지 않는다.

음성 서버는 키가 있으면 `--filter auto`에서 JEV를 선택한다. 저장 후 `systemctl --user restart switch-voice-server.service`로 반영한다.

재실행 도구는 `hardware/kiosk_audio_monitor/compare_speech_gates.py`. 키가 설정된 서버 환경에서 `--live --providers both --repeats 1`을 사용한다. `--service-fast-path`를 붙이면 Python 빠른 규칙까지 포함하며 모델 자체 비교와 구분해야 한다.

원본 JSON·CSV는 `output/voice-comparison/`에 보관한다.
