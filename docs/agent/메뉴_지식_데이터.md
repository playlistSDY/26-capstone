# 메뉴 설명과 성분 지식 데이터

에이전트는 113개 데모 메뉴의 정보를 `order-agent/data/menu-knowledge.json`에서 조회한다. 화면의 모든 상품 카드에 영양표를 노출하지 않고 read_menu와 find_suitable_menu에 전달한다. 데이터는 자세하게 유지하고 고객 응답은 필요한 한두 문장으로 제한한다.

## 자료와 매칭 범위

2026년 11월 20일 [이디야 공식 음료 페이지](https://ediya.com/contents/drink.html)와 해당 페이지가 사용하는 `menu_more` 응답에서 공식 음료 변형 411건을 확인했다. 페이지의 실제 메뉴 상세 `nutri_` 항목만 추출하고, 상단의 정적 예시 설명은 수집 대상에서 제외했다.

2026년 11월 23일 메뉴 개편을 반영해 113개 메뉴와 판매 가능한 284개 온도·크기·디카페인 조합을 연결했다. 기존 공식 수집 자료를 재사용했으며 281개 조합의 당류·카페인 값은 공식 자료에서 가져왔다. 이디야 워터와 디카페인 아샷추의 누락 정보는 출처를 표시한 데모 가정으로 채웠다. 이전 112개·323개 조합 집계에는 현재 판매하지 않는 온도·원두 조합도 포함되어 있었다.

메뉴마다 설명, 관련 재료, 배합 예시, 온도·크기·디카페인별 당류·카페인·열량·단백질·포화지방·나트륨·용량, 알레르기 주의 재료, 출처와 확인 시각을 저장한다. 공식 목록의 L은 데모 regular, EX는 large의 비교 기준으로 사용한다. 데모 실제 컵·옵션·원재료가 공식 매장과 동일하다는 보장은 아니다.

## 공식 정보와 데모 추정

`values`에는 수치를, 같은 키의 `value_origins`에는 official 또는 demo_estimate를 저장한다. 알레르기는 allergen_origin, 재료 이름의 근거는 ingredients.origin, 재료 배합량은 amount_origin으로 구분한다. source_url과 official_id를 함께 보관한다.

공식 배합량이 공개되지 않은 재료도 사용자의 요청에 따라 데모 수치로 채웠다. 예를 들어 우유·정제수·커피 베이스와 향미 재료에 일반적인 배합을 가정한 양과 단위를 부여한다. 이 값은 실제 이디야 제조법이나 원재료 함유율이 아니다. `ingredient_amounts_demo`와 각 재료의 `amount_demo`는 모두 데모 가정으로 취급한다.

공식 알레르기 표시가 없으면 데모 메뉴명과 일반적인 재료로 예상 주의 재료를 채운다. 빈 주의 재료 목록은 별도의 설명 문구와 함께 저장하며, 실제 무알레르기·교차 접촉 없음으로 해석하지 않는다. 원본 출처는 그대로 보존한다. 고객 응대에서는 아래 데모 매장 설정을 사용하며 이를 실제 이디야 공식 제조법이라고 표현하지 않는다.

## 쉬운 분류와 답변

당류 등급은 한 잔 기준 0g, 15g 이하, 35g 이하, 35g 초과로 구분하고 sugar_level에 저장한다. 느껴지는 단맛인 sweetness는 메뉴 종류·향미와 당류를 함께 고려한 별도 데모 추정이다. 제로슈가·감미료·향미 음료는 당류가 낮아도 단맛으로 분류한다. 당류 없음과 안 달다는 같은 의미가 아니며, 이 분류는 건강 기준도 아니다.

카페인은 0mg을 ‘없음’, 0mg 초과 50mg 이하를 ‘적음’, 50mg 초과 150mg 미만을 ‘보통’, 150mg 이상을 ‘많음’으로 구분한다. 디카페인이라도 실제 값이 0보다 크면 카페인 없는 후보에 포함하지 않는다.

고객이 “많이 달아요?”라고 물으면 짧게 맛을 안내한다. “당류가 몇 g이에요?”라고 물으면 해당 조합의 수치와 단위를 답한다. 등록된 데모 매장 수치는 단위와 함께 분명하게 안내한다. 실제 이디야 공식 정보인지 질문할 때 출처를 구분하며, 일반 응답마다 추정 표시를 읽지 않는다. 우유를 피하는 고객에게는 관련 주의 재료와 대안만 짧게 안내하고 모든 성분을 나열하지 않는다.

## 추천 도구

find_suitable_menu는 카페인 없음/적음, 당류가 적은 편/단 편, 피할 재료, 최대 가격을 동시에 적용한다. 품절 상품은 제외하고 디카페인 추가 금액도 포함한다. 실제 음료를 담는 동작과 추천은 구분한다.

일반 알레르기 표시 외에 메뉴명과 주요 재료도 함께 비교한다. 캐모마일처럼 표준 알레르기 목록 밖의 재료도 제외하며 캐모마일·카모마일·Chamomile, 계란·달걀, 두유·대두, 견과류·아몬드 등의 표현을 정규화한다. 이 정규화는 데이터 검색을 위한 것이며 알레르기 진단이나 개인별 안전 판단 기능이 아니다. 출처 표시는 내부에 유지하고, 고객에게는 조건에 맞는 후보와 짧은 이유를 분명하게 안내한다.

## 갱신

메뉴 배치·옵션 변경만 반영할 때는 아래 동기화를 먼저 실행한다. 기존 출처를 유지하면서 지원하지 않는 조합을 제외하고 새 ID에 기존 메뉴 지식을 연결한다.

```sh
python3 order-agent/scripts/sync_kiosk_catalog.py
```

공식 자료를 다시 수집할 때:

```sh
python3 order-agent/scripts/import_ediya_knowledge.py
```

스크립트는 `tmp/ediya-source/`에 읽은 공식 페이지를 캐시하고, 메뉴 지식 JSON을 갱신한다. 새 공식 자료를 다시 수집하려면 해당 캐시를 별도 보관하거나 비운 뒤 실행한다. 캐시는 Git에서 제외한다. 갱신 후에는 이름·온도·크기·디카페인 매칭, 수치 출처, 알레르기 필터 테스트를 실행한다.

에이전트 서버는 지식을 메모리에 캐시하므로 데이터 갱신 후 서버를 재시작해야 한다. 운영용으로는 매장 데이터 제공 API와 변경 이벤트로 교체하는 것을 권장한다.

실제 이디야 매장별 제조 설비는 확인한 정보가 아니다. 이번 데모 매장은 아래 별도 정책 파일에 공용 도구 사용과 미량 접촉 차단 메뉴 미제공을 명시적으로 설정했다. 대체 메뉴를 요청한 고객에게는 조건에 맞는 후보와 짧은 이유를 먼저 말하고, 안전성·제조 과정을 직접 질문했을 때 확인 범위를 설명한다.


## 확정된 데모 매장 설정으로 응대

`order-agent/data/store-service-policy.json`은 가상의 SWitch 매장 제조·응대 설정이다. `read_menu.menu_information.store_profile`은 113개 메뉴 모두에 메뉴 설명, 재료별 배합량·단위, 온도·크기·디카페인별 영양·단맛·카페인·주의 재료, 제조 변경 정책을 제공한다. 원본의 공식값/추정값 출처는 별도로 유지한다. 배합량은 등록된 기본 배합 예시이고 옵션별 영양 수치를 재계산한 값은 아니다.

‘덜 달게’는 조절 가능한 첨가 시럽·베이스 절반, ‘얼음 적게’는 기본 얼음의 절반, 우유 대체는 대체 가능한 우유 부분을 같은 양의 오트밀크로 변경하는 설정이다. 원재료 자체의 당과 소스·분말의 우유 성분까지 제거되는 것은 아니다. 실제 매장 API 연결 시 해당 매장의 확정 레시피로 교체해야 한다.

손님에게는 ‘우유가 들어가요’, ‘카페인이 없어요’, ‘기본 시럽을 절반으로 넣어 드려요’처럼 설정을 바로 안내한다. ‘~같아요’, ‘아마’, ‘확인이 필요해요’, ‘잘 모르겠어요’를 등록된 정보에 붙이지 않는다. 일반 응답마다 ‘데모 기준/추정’도 반복하지 않는다. 화면의 가상 주문 표시와 내부 출처는 유지하고, 실제 이디야 공식 정보인지 직접 물으면 구별한다.

제조 도구 공용 사용은 이번 가상 매장의 명시적 설정이다. 제조 과정이나 안전성을 질문할 때 설정대로 직접 설명한다. 일반 추천에 불필요하게 덧붙이지 않고, 알레르기 안전 보증이나 실제 결제 완료는 만들어 내지 않는다.


## 개편된 옵션 계약

`ice=more`는 얼음 많이, `whippedCream=normal|extra|none`은 기본·추가·제거다.
휘핑 지원 메뉴만 변경하며 두 옵션의 추가금은 0원이다. `decafOnly=true`인
메뉴는 디카페인 기본값과 포함 가격을 사용하고 일반 원두로 바꾸지 않는다.
휘핑 제거는 소스·분말·우유의 알레르기 성분을 제거하지 않는다.
디카페인 아샷추는 홍차 35mg과 디카페인 샷 7mg을 가정한 별도 데모 배합이며
카페인 0mg으로 추천하지 않는다. 큰 크기는 1.4배로 가정한다.
