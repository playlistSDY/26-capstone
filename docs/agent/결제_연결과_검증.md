# 에이전트와 키오스크 결제 연결

## 고객 응대 흐름

1. “결제할래”, “주문 다 한 것 같아”, “이걸로 할게”를 주문 마무리 의도로 해석한다. 미확정 옵션·매장/포장을 먼저 마친다.
2. request_final_confirmation은 기존 주문 확인 화면(cart)을 열고 메뉴·옵션·수량·금액을 읽는다. 대화창에도 같은 주문과 금액을 표시한다.
3. 읽기가 끝난 다음 손님의 동의를 받으면 open_checkout으로 결제수단 선택 화면으로 이동한다. 마무리 의도 자체는 최종 동의를 대신하지 않는다.
4. 카드·삼성페이·애플페이·카카오페이·네이버페이 중 원하는 수단을 select_payment_method로 연다. 동의 발화에서 수단을 함께 지정한 경우 open_checkout(method=...)으로 바로 반영한다.
5. 기존 PaymentFlow의 리더기 대기 → 인식 → 승인 → 완료 흐름을 사용한다. 손님에게 카드/휴대폰/결제코드 제시 방법을 짧게 안내한다. 리더기 결과를 기다리며 ‘카드 넣었어’라는 말만으로 성공을 만들지 않는다.
6. 실패·시간 초과는 UI 결과가 들어오는 즉시 짧게 알리고 재시도를 제안한다. 고객 동의 후 retry_payment, 수단 변경은 select_payment_method, 승인 전 취소는 cancel_payment로 처리한다. 주문과 옵션은 유지한다.
7. 키오스크가 주문 저장까지 마친 결과를 전달하면 결제 완료와 실제 생성된 주문번호를 안내한다. 완료 안내가 재생된 뒤 서버 세션과 대화 이력을 끝낸다. 홈으로 초기화할 때도 이전 세션을 종료한다.

채팅은 상단 네비바 아래 작업 영역에서 키오스크 오른쪽에 항상 표시하는 비모달 패널이다. 두 영역은 겹치지 않으며 기존 화면·리더기를 터치할 수 있다. 좁은 창에서는 가로 스크롤로 두 영역을 유지한다. 완료 안내 중에는 홈 자동 복귀 카운트다운을 멈추고, 안내가 끝나면 기존 완료 화면과 홈 복귀 흐름을 이어 간다. 음성을 끈 경우 텍스트 결과 표시 후 세션을 종료한다.

## 상태와 중복 방지

서버 snapshot은 view(review/payment), payment_ui(UI가 보낸 결제 상태·완료 영수증), payment_action(실행할 명령)을 제공한다. 명령에는 고유 id, kind(select/retry/cancel), method, expected_attempt, total이 들어간다. 브라우저는 금액·현재 시도 ID·현재 상태가 일치할 때 한 번만 기존 결제 함수를 실행하고 last_action_id로 반영을 알린다. 중복 응답으로 새 결제 시도를 만들지 않는다.

리더기가 읽거나 승인 중이면 다른 수단으로 덮어쓰지 않고 먼저 취소하도록 한다. 승인 완료 후 재시도·취소·주문 수정을 차단한다. 완료된 주문은 늦은 UI 스냅샷으로 다시 열지 않는다. 미확정 옵션과 최종 요약의 전달 확인 게이트는 유지한다.

브라우저는 실패·시간 초과·주문 저장 완료를 내부 payment_event 요청으로 전달한다. 서버가 UI 상태에서 문장을 생성하므로 이 알림에는 LLM을 호출하지 않는다. 같은 스트리밍/TTS 경로를 사용하며 손님의 발화로 기록하지 않는다. POST /agent-api/sessions/{id}/end는 세션·대화·대기 작업·음성 연결을 종료한다.

## 구현 범위

현재 결제 결과는 기존 데모 키오스크의 리더기 시뮬레이션이다. 실제 카드 청구·PG 승인·환불은 구현되지 않았다. 에이전트가 임의로 승인 결과를 생성하는 도구는 없다. 실제 매장 연결 시 UI 알림 대신 인증된 결제 서버의 시도 ID·견적 ID·승인 이벤트를 기준으로 완료를 확정해야 한다.

## 검증

- Python 81개: 최종 확인, 중요 옵션, 결제수단 5종, 중복 명령·UI 반영, 실패 재시도, 승인 중 변경 제한, 취소 후 재확인, 승인 후 재결제 차단, 영수증 검증, 완료 세션 종료를 포함한다.
- 웹 단위 테스트 30개: 결제 명령의 금액·시도 ID 검증, 상태별 허용 동작과 기존 주문·음성 규칙을 포함한다.
- 브라우저: 에이전트 결제 성공·실패/재시도/취소 2개 시나리오, 상시 패널의 화면 크기별 분리 배치·네비바 유지와 기존 5종 결제수단 시나리오를 확인한다. 에이전트 응답을 고정한 테스트이며 주문 저장·리더기·영수증 흐름은 실제 프런트엔드 코드를 실행한다.
- 실제 GPT-6.2 Sol: ‘주문 다 한 것 같아’ → 주문 확인 화면 요청, ‘네’ → 결제수단 선택, ‘카드로 결제할게’ → 카드 리더기 명령, 실패 UI 상태 후 ‘다시 해줘’ → 재시도 명령을 확인했다.


## 공개 AI 키오스크 배포 확인

[AI 키오스크 공개 주소](https://temp.sdy.world/980d563c-35d0-4ee2-9de0-161a08901e29/)에 결제 연동 코드를 포함해 배포했다. 실제 공개 브라우저와 GPT-6.2 Sol에서 ‘주문할게요’ → 매장/포장 질문 → ‘포장해 주세요’ → 메뉴판 이동 → 아메리카노 추가 → ‘주문 다 한 것 같아요. 결제할래요’ → 주문 확인 → ‘네 카드로 결제할게요’ → 기존 리더기 → 완료 화면을 확인했다. 저장된 주문은 카드 3,200원 한 건이며, 완료 후 세션 종료와 대화 초기화도 확인했다. 청구는 없는 데모 결제다. 운영 경로와 중앙 서버 설정은 [sdylab 통합 운영](sdylab_통합운영.md)을 참고한다.
