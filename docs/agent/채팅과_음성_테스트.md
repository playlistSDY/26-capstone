# 키오스크 채팅과 음성 테스트

로컬 키오스크 화면 오른쪽 아래의 ‘주문 대화 테스트’로 에이전트를 시험한다. 채팅은 현재 장바구니를 가져오며, 대화로 바꾼 메뉴·옵션·수량을 화면에 반영한다. 이 모달은 테스트용이며 최종 고객용 UI/UX를 확정한 결과가 아니다.

## 설정과 실행

`order-agent/.env`에 API 키와 모델을 설정한다. 실제 키는 브라우저나 채팅 메시지로 보내지 않는다. `.env`는 Git 추적에서 제외한다.

```dotenv
OPENAI_API_KEY=발급받은_API_키
OPENAI_MODEL=gpt-6.2-sol
OPENAI_TTS_MODEL=gpt-realtime-2.1-mini
OPENAI_TTS_VOICE=cedar
```

음성 설정을 생략하면 위 TTS 모델·음색을 기본값으로 사용한다. 대화 모델과 음성 모델은 별도다. GPT-6.2 Sol은 대화와 도구 판단을 담당하고, Realtime 모델에는 생성된 안내문만 보내 낭독하도록 한다. 마이크·STT 입력은 사용하지 않는다.

1. `order-agent/에이전트_서버.command`를 실행한다. 또는 order-agent에서 `.venv/bin/python -m switch_agent.web`을 실행한다.
2. kiosk-web에서 `npm run dev`를 실행한다.
3. [로컬 키오스크](http://127.0.0.1:5173/)의 채팅 모달을 연다.

설정이나 에이전트 코드를 바꾼 뒤에는 서버를 재시작한다. 모달에서 ‘다시 연결’, ‘새 대화’를 누르면 키오스크에 담긴 주문은 유지하면서 새 세션이 현재 장바구니를 가져온다. 프론트엔드 코드가 크게 바뀐 개발 중에는 새로고침이 필요할 수 있다.

## 동작

- 답변 텍스트는 SDK의 text delta 이벤트를 받아 점차 표시한다. 도구 실행 중에는 확인 중이라는 상태를 표시한다.
- 음성은 완성된 문장을 순서대로 요청하고 24kHz PCM 조각이 도착하는 즉시 Web Audio로 재생한다. 전체 파일 완성까지 기다리지 않는다. 대화 세션마다 Realtime 연결을 미리 열고 재사용하며 다음 문장은 앞 문장 재생 중 미리 준비한다. 음성은 AI가 생성한 것임을 모달에 표시한다.
- ‘말 끊기’ 또는 답변 중 새 메시지 전송은 SDK 생성, 현재 재생, 음성 요청과 대기열을 중단한다. 이미 반영된 주문은 유지한다.
- 요약 전달 ACK와 낭독 완료는 결제수단 화면으로의 이동을 막지 않는다. 고객의 진행 의사는 모델이 문맥으로 판단하며, 음성 재생 실패 시 화면 텍스트로 계속 진행한다. ‘음성 끄기’는 화면의 전체 텍스트로 계속하는 명시적인 선택이다.
- 모달을 닫았다 열면 대화가 유지된다. 키오스크를 처음부터 시작하면 대화도 새로 만든다. 모달을 연 동안 유휴 초기화는 멈춘다.
- 연결이 끊기면 ‘응답 다시 확인’으로 같은 요청 ID의 이벤트를 이어받는다. 새 요청 ID로 같은 주문을 자동 반복하지 않는다.

브라우저·장치에 따라 오디오 재생 권한이나 출력 장치를 확인해야 할 수 있다. 재생 실패는 화면에 표시하되 화면 텍스트로 주문·결제를 계속할 수 있다. 브라우저 내장 TTS로 조용히 바꾸는 동작은 없다.

## 로컬 브리지 계약

| 경로 | 역할 |
| --- | --- |
| GET `/agent-api/status` | 모델 설정 여부와 요청 토큰 확인 |
| POST `/agent-api/sessions` | 독립적인 대화 세션 생성 |
| POST `/agent-api/sessions/{id}/turns` | 요청 ID·텍스트·현재 화면 장바구니로 턴 시작 |
| GET `/agent-api/sessions/{id}/turns/{request_id}/events?after=N` | NDJSON 이벤트 스트림과 재접속 시 이어받기 |
| POST `/agent-api/sessions/{id}/interrupt` | 생성·TTS 중단과 반영된 최신 주문 조회 |
| POST `/agent-api/sessions/{id}/speech` | 해당 턴에서 실제 생성한 안내 문장만 음성으로 생성 |
| POST `/agent-api/sessions/{id}/end` | 대화 이력·작업·음성 연결 종료 |
| POST `/agent-api/sessions/{id}/delivered` | 최신 완료 응답의 전체 전달 확인 |

변경과 스트림 요청에는 로컬 서버가 발급한 X-Switch-Agent-Token을 사용한다. 서버는 loopback에만 바인딩하며 허용된 로컬 Origin을 확인한다. 동일 요청 ID는 내용을 검증해 결과를 재사용한다. TTS도 동일 턴·동일 문장의 결과를 캐시해 재요청 비용을 줄인다.

화면 장바구니가 달라지면 다음 턴에 가져오고 최종 확인을 무효화한다. 응답 대기 중 화면 주문이 예상치 않게 바뀌면 오래된 결과로 덮어쓰지 않는다. 서버 재시작 시 세션은 사라지지만 브라우저가 저장한 장바구니는 별개로 유지된다.

이 브리지는 개발용이다. Windows 배포 패키지나 기존 공개 라이브 뷰에 자동 포함·배포하지 않는다. 실제 매장 API와 다중 기기 장바구니 동기화의 대체물이 아니다.

## OpenAI 음성 경로를 고른 이유

브라우저 내장 음성의 발음·말투가 기대와 달라 OpenAI 음성으로 교체했다. [공식 음성 안내](https://developers.openai.com/api/docs/guides/text-to-speech)는 기존 Speech API 모델의 종료 일정과 Realtime API 이전을 안내하므로, 신규 경로는 [Realtime 음성 출력](https://developers.openai.com/api/docs/guides/realtime-conversations)을 사용한다. 모델 음색과 대화 지침을 분리해 조절하며 실제 자연스러움은 고객 평가로 확인한다.

## 음성 지연 확인

재사용한 Realtime 연결에서 짧은 한국어 두 문장을 시험했을 때 첫 음성 조각은 각각 약 1.13초·0.87초, 전체 생성은 약 1.60초·1.07초였다. 모델에 문장을 전송한 시점부터의 직접 API 측정이며, 주문 판단·브라우저 재생·네트워크 전체를 포함한 종단 지연은 아니다. 요청마다 지연은 달라질 수 있다.

PCM 재생 테스트는 audio.done 이전에 첫 조각이 예약되는지, 최종 재생 완료 전 확인을 통과시키지 않는지, 끼어들면 예약된 소스를 중단하는지 검사한다.


주문 종료 표현을 말하면 주문 확인 화면을 열고 확인받는다. 동의 후 결제수단을 말하면 기존 리더기 화면이 열린다. 실패·시간 초과·주문 저장 완료는 payment_event로 전달하고, 서버가 LLM 호출 없이 짧은 안내를 생성해 같은 TTS 경로로 읽는다. 대화창은 상단 네비바 아래 키오스크 옆에 항상 표시하는 비모달 패널이므로 화면 터치도 가능하다. 패널 표시 자체는 활성 대화로 간주하지 않아, 대화하지 않은 주문의 완료 후 홈 복귀도 정상 진행한다. [결제 연결과 검증](결제_연결과_검증.md)을 참고한다.

## 남성 음색 변경 (2026-11-23)

남성 음색으로 Cedar를 선택했다. 중앙 서버의 `OPENAI_TTS_VOICE=cedar`, 코드의 기본값과 예시 환경 설정을 함께 맞췄다. 기존 Realtime 연결의 음색이 남지 않도록 중앙 에이전트를 재시작했다. 실제 Realtime 스트리밍 경로로 한국어 안내의 PCM 112,800바이트를 생성했고 Python 106개 테스트도 통과했다. 이미 재생 중인 문장보다 새 연결의 응답부터 적용되므로 테스트 화면은 새로고침한다. [OpenAI 음색 설정 안내](https://developers.openai.com/api/docs/guides/realtime-conversations#voice-options)
