# 음성 입력 웹 화면

`hardware/kiosk_audio_monitor/마이크_웹.command`를 실행한다. 기본 주소는 http://127.0.0.1:18733/ 이며 Mac의 ESP USB 포트를 별도 브라우저 마이크 권한 없이 수신한다. 기존 마이크 CLI/시리얼 모니터는 먼저 종료한다.

## 화면 구성

- 가운데 ‘나’ 아바타 위 말풍선: 에이전트에 전달할 발화 원문. 단어/단답/정정/대명사 요청도 표시한다. 이는 주문 실행 완료를 의미하지 않는다.
- 오른쪽 인식 중인 말: STT 후보와 발화 합치기/대상 판단 상태. 명백한 주변 대화나 입력 오류는 이곳과 로그에서 확인한다.
- 처리 시간: STT 요청 시간, 의미 판단 시간, STT 완료부터 최종 판단까지, VAD 발화 끝부터 최종 판단까지. 로컬 빠른 경로와 의미 모델 경로를 표시한다.
- 처리 로그: 기본은 주요 이벤트만 표시하고 마이크 수치는 별도로 분리한다. 자세히는 초당 진단 수치를 추가하며, 비우기는 화면의 로그만 지운다.
- 오른쪽 위: 수음 시작/중지. 중지하면 자신이 실행한 수음기와 USB 포트를 해제한다. 웹 서버 종료는 실행 터미널에서 Ctrl+C다.

아바타는 개인 사진을 사용하지 않은 기본 벡터 캐릭터다. 입력 레벨 막대는 실제 수신 RMS를 시간순으로 표시한다. 브라우저 새로고침 시 실행 중인 서버의 최근 이력을 재사용한다. 같은 실행 파일을 다시 열면 기존 서버에 연결한다.

## 구현 경계

이 화면은 중앙 주문 에이전트를 호출하기 전 입력 테스트다. 주문/결제 API를 호출하지 않으며, 전달할 원문을 표시한다. 실제 의미와 참조를 해결하는 것은 뒤의 에이전트 역할이다. 메뉴 패턴은 속도를 위한 경로일 뿐 허용 목록이 아니다.

로컬 HTTP 서버는 127.0.0.1에만 바인딩하고, 수음 제어에는 같은 출처와 실행 시 만든 토큰을 요구한다. 정적 파일은 화면/캐릭터/기존 로컬 글꼴만 제공하며 .env나 임의 경로를 제공하지 않는다. API 키는 브라우저에 보내지 않는다. 원음은 디스크에 저장하지 않으며 웹 로그/최근 전달 이력은 서버 메모리에서만 유지한다. 모델 STT/의미 판단에는 별도 인터넷 연결이 필요하다.

## 검증

```sh
cd hardware/kiosk_audio_monitor
.venv/bin/python -m unittest discover -p 'test_*.py'
node check_voice_dashboard.mjs
```

브라우저 검증은 kiosk-web에 설치된 Playwright를 재사용한다. 별도 임시 서버와 합성 이벤트로 HTTP/SSE, 확정 말풍선/후보 분리, 중지/시작, 새로고침, 원문 escaping, 1360/1024/390px 폭을 검증한다. 마이크/API는 이 브라우저 자동 시험에서 사용하지 않는다. 결과와 스크린샷은 tmp/voice-dashboard-qa에 저장한다.

실제 수음과 속도는 별도로 연결해 확인하며 단일 사례의 지연을 모든 발화의 성능 보장으로 표현하지 않는다. [필터 구성과 현장 평가](음성입력_필터_시제품.md)를 참조한다.
