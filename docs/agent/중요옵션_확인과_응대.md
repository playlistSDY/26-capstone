# 중요 옵션 확인과 응대

메뉴를 담기 전에 온도 → 사이즈 → 얼음 → 당도 순서로, 적용 가능한 항목 하나씩 확인한다. 사용자가 이미 말한 선택은 건너뛴다. 질문마다 기본안을 짧게 제시하고, 손님이 답하면 이어 간다. “네”는 직전 옵션 질문에 대한 답이지 주문 전체의 결제 동의가 아니다.

예: “아이스 바닐라라떼 하나” → “기본 크기로 드릴까요? 큰 크기는 500원 추가예요.” → “네” → “얼음은 보통으로 넣어 드릴까요?” → “적게요” → “당도는 기본으로 해 드릴까요? 덜 달게도 가능해요.” → “덜 달게” → 추가 도구 성공 후 “기본 크기, 얼음 적게, 덜 달게 한 잔 담았어요.”처럼 선택 결과만 짧게 안내한다.

“아이스 큰 걸로 얼음 적게 덜 달게”는 재질문 없이 담는다. “나머지는 기본으로 해줘”는 명시적 위임이므로 남은 선택을 생략한다. 온도는 여러 가지라면 위임만으로 추측하지 않는다. 뜨거운 음료의 얼음, 기본적으로 달지 않은 음료의 당도, 고정 상품의 사이즈는 묻지 않는다.

미확정 추가는 서버 `item_drafts`에 남고 장바구니·금액에 반영되지 않는다. add_item은 `needs_preference` 또는 `added`를 반환한다. 확인한 값이 바뀌면 해당 옵션의 확인을 다시 요구한다. 고객 질문·끼어들기 중에도 요청을 유지하고, 포기하면 cancel_pending_item으로 지운다. 전체 주문 취소는 장바구니와 미확정 추가를 함께 비운다. 미확정 요청이 남으면 최종 결제 확인을 차단한다. 같은 상품의 미확정 요청은 하나이므로 서로 다른 옵션의 같은 상품 여러 잔은 한 조합을 마친 다음 다음 조합을 진행한다.

서버는 미확정 옵션의 존재와 값별 확인을 검증한다. ‘실제 발화가 어떤 옵션에 동의했는가’는 현재 모델의 문맥 해석을 사용하며 독립된 의미 판정기가 보증하지 않는다. 실제 고객 응대 품질은 별도 시나리오 평가가 필요하다.

## 참고한 공개 자료

- [Starbucks: Ways to customize your beverage](https://about.starbucks.com/stories/2025/ways-to-customize-your-beverage-at-starbucks/): 단맛·우유·카페인 등 개인 취향에 맞춘 선택 안내.
- [Starbucks: Barista Customization Tips](https://about.starbucks.com/uploads/2024/06/Beverage-Health-and-Wellness-Fact-Sheet-June-2024-3.pdf): 재료 정보와 선택 가능한 맞춤 주문 안내.

이는 공개 고객 안내 자료이며 내부 직원 응대 매뉴얼을 열람한 것은 아니다. ‘한 질문씩 기본안 제시’와 질문 순서는 이 프로젝트의 시니어·아동 고객 요구에 맞춘 설계다. 스타벅스의 레시피·사이즈·가격을 이디야 데모에 가져오지 않는다.

## 확인 결과

2026-11-21 실제 설정 모델(GPT-6.2 Sol)에서 “아이스 바닐라라떼 한 잔 주세요” → “네” → “얼음 적게요” → “덜 달게 해줘”를 실행했다. 사이즈·얼음·당도 순으로 한 가지씩 묻고, 앞선 세 턴에는 장바구니가 비어 있었으며 마지막 턴에만 한 잔을 담고 미확정 요청이 사라지는 것을 확인했다. 자동 테스트는 총 57개 통과했다.
