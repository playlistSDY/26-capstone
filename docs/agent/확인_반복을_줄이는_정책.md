# 반복 확인을 줄이는 주문·결제 정책

2026-11-21 사용자 피드백을 반영했다. 결제수단 선택 화면의 이동은 승인이나 청구가 아니므로 음성 낭독·요약 전달 ACK·새 발화 여부·확인 토큰·요약 버전을 진입 조건으로 쓰지 않는다. 동의와 진행 의사는 모델이 대화 맥락으로 판단한다.

처음 주문을 마치려 할 때는 주문 확인 화면을 한 번 보여 준다. 이미 그 화면에 있으면 ‘그래/맞아/ㅇㅇ/이대로 결제해줘’에 open_checkout으로 이어 간다. 매장/포장만 바꾸면 그 값을 반영하고 다음 단계로 간다. 전체 주문을 다시 읽거나 같은 동의를 반복하지 않는다.

open_checkout은 현재 장바구니·매장/포장·판매 가능 상태를 확인하고 결제수단 선택을 연다. 빈 주문과 미선택 이용 방법만 짧게 해결한다. 반복 호출해도 새 결제 시도나 승인을 만들지 않는다. 실제 결제 승인·완료·재시도·취소 상태는 기존 키오스크 리더기에서 받는다. 승인 완료 시도를 다시 청구하거나 임의로 성공으로 만드는 도구는 없다.

/ delivered는 구형 클라이언트용 호환 응답으로 남기며 결제 진입을 제어하지 않는다. 새 서버 응답은 needs_delivery=false를 반환하므로 TTS 실패나 읽는 도중의 발화로 결제 진행이 막히지 않는다.

사이즈·얼음·당도의 남은 기본 옵션은 question_options로 묶어 한 번에 제안한다. ‘네’는 그 질문에 포함된 선택에 동의한 것으로, ‘기본으로’는 남은 기본 옵션까지 적용하는 것으로 처리한다. 온도 등 실제로 빠진 선택만 따로 확인한다.

회귀 검증은 ‘이대로 결제해줘 → 매장에서 먹고갈래 → 그래’에서 새 요약의 ACK가 없어도 결제수단으로 넘어가는 SDK 흐름, 음성 실패 상태의 브라우저 흐름, 중복 결제 진입의 무청구·멱등성, 묶음 옵션 확인을 포함한다. Python 101개, 관련 브라우저 10개 시나리오를 통과했다.

공개 서버에서도 제보와 같은 카페모카 2잔·큰 아이스 아메리카노 1잔(12,100원)을 사용해 검증했다. 음성을 의도적으로 실패시킨 상태에서 ‘이대로 결제해줘 → 아 매장에서 먹고갈래’가 바로 결제수단 선택으로 이어지고, 카드 선택 후 완료 화면까지 진행됐다. 음성 실패는 화면 텍스트로 계속하며 완료 안내 콜백도 막지 않는다. 결제수단 화면에서 아직 리더기를 시작하지 않았다면 이용 방법을 바로 바꿀 수 있다.
