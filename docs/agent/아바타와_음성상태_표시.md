# 키오스크 안에서 움직이는 점원 아바타

2026-11-23. 채팅창에 붙인 캐릭터가 아니라, 키오스크 화면 안에서 주문·설명·안내를 담당하는 캐릭터를 구현한다. 지금의 텍스트 입력은 STT를 대신하는 테스트 도구이며 제품의 중심 UI로 취급하지 않는다. 기본 작업 실행은 계속 에이전트가 직접 담당한다.

## 화면 구성

- 사용자가 제공한 `Frame 92.png`의 점원 모습을 기준으로 아바타를 만든다. 원본과 애니메이션용 투명 이미지 시트를 `kiosk-web/public/agent/`에 보관한다.
- 큰 채팅 사이드바를 제거했다. 캐릭터·현재 상태·현재 자막·‘내 말’을 키오스크 안의 말풍선에 표시한다. 대화 기록은 캐릭터 옆 ‘대화 내역’을 눌렀을 때만 키오스크 안에 연다.
- 하단의 작은 텍스트 입력줄은 STT 대용 개발 입력이다. 음성 켜기·말 끊기·세션 사용량·새 대화도 테스트용으로 유지한다. 실제 입력 장치를 연결하면 이 입력줄을 교체할 수 있다.
- 현재 입력 중인 텍스트와 마지막 전송 문장을 ‘내 말’에 표시한다. 앞으로 STT 중간 텍스트를 받으면 같은 자리에 표시할 수 있다. 주문 도구 실행 기준은 계속 수락한 최종 발화다.

## 캐릭터 위치와 설명 대상

`KioskCompanion`은 `.kiosk` 안에 렌더링된다. 기기의 800×1280 기준 좌표를 사용하고 미리보기의 배율·창 크기를 반영한다. 대화창이나 브라우저 밖의 별도 아바타 영역이 아니다.

안내 중인 버튼·옵션은 기존 `guidance`의 의미 ID로 찾는다. 해당 요소 주변의 후보 위치와 현재 보이는 버튼·이미지·제목·설명 등의 경계를 비교한다. 정착 위치가 겹치지 않는 후보를 선택하고 위치 변화는 부드럽게 연결한다. 주문 확인 화면처럼 여백이 있으면 그 공간으로 이동할 수 있다.

안전한 후보가 없으면 키오스크 하단에 확보한 180px 영역으로 이동한다. 이 공간만큼 메뉴·주문 내용과 옵션 모달의 사용 높이를 줄여 결제 버튼과 담기 버튼을 아바타 밑에 숨기지 않는다. 메뉴와 옵션 내용은 기존 스크롤을 유지한다. 이는 정착 위치의 화면 요소 경계에 따른 배치이며, 실물 하드웨어에서의 시선·가림 사용자 평가를 완료했다는 뜻은 아니다.

## 입·눈·손 모션

- 제공된 점원 원본을 기반으로 만든 네 가지 표정·포즈를 합성한다. 눈 깜빡임은 별도 영역으로 적용하여 말하는 입과 독립적으로 동작한다.
- 평소에는 작은 숨쉬기 동작과 간헐적인 손짓을 사용하고 말하는 동안에는 작은 설명 손짓을 사용한다.
- 입 모양은 실제 재생되는 24kHz PCM의 40ms 구간별 크기와 Web Audio 재생 시각에 연결한다. 응답 글자 수나 임의의 말하기 타이머로 움직이지 않는다.
- 문장 생성·오디오 다운로드 대기 중에는 입을 닫는다. 음성의 무음 구간에서는 재생 중 상태를 유지하되 입은 닫고, 말 끊기·음소거·재생 완료·오류에는 입을 닫고 측정 타이머를 정리한다. 이전 요청의 늦은 콜백은 세션·요청 세대로 차단한다.
- 이번 구현은 음량 기반의 입 열림이며 한국어 음소별 정밀 입술 모양이나 얼굴 추적은 아니다. 입력 음성·영상은 추가 수집하지 않는다.
- 기기의 ‘동작 줄이기’ 설정에서는 상시 손짓·호흡·눈 깜빡임·위치 전환 애니메이션을 줄인다. 대화 상태·자막은 유지한다.

## 상태 표시와 입력 어댑터

| 상태 | 실제 근거 |
| --- | --- |
| 입력 대기 / 입력 중 | 현재 텍스트 대용 입력 상태 |
| 답변 준비 중 | 주문 요청 처리 중이고 실제 출력 PCM은 아직 재생하지 않음 |
| 음성 준비 중 | TTS가 대기·준비 중이며 실제 출력 PCM은 아직 재생하지 않음 |
| 말하는 중 | Web Audio의 현재 시각이 실제 출력 구간에 포함됨 |
| 연결 확인 중 | 중앙 서버 연결 준비 또는 연결 불가 |
| 듣고 있어요 / 말씀 듣는 중 / 말씀 확인 중 | 향후 입력 어댑터가 실제 listening/speech/transcribing 상태를 전달했을 때만 표시 |

`AgentChat`의 선택적 `voiceInput` 계약은 `phase=off/listening/speech/transcribing/error`, `partial?`이다. 앞으로 연결할 입력 어댑터는 현재 대화 세션에 속한 입력만 전달하고 세션 종료·마이크 중단 때 phase와 partial을 비워야 한다. 단순히 대화가 열렸거나 글자를 입력했다는 이유로 마이크가 듣는다고 표시하지 않는다. 현재 이 화면에는 마이크·STT 수집 코드를 추가하지 않았다.

## 구현 위치

- `AgentAvatar.tsx` / `agent-avatar.css`: 표정·손·눈·입의 이미지 합성과 모션.
- `KioskCompanion.tsx` / `kiosk-companion.css`: 실제 키오스크 안의 배치·자막·내 말·대화 기록 진입.
- `attendantState.ts`: 입력·처리·음성 준비·실제 재생 상태 구분.
- `audioActivity.ts` / `agentAudio.ts`: PCM 크기·실제 재생 시각과 중단 처리.
- `AgentChat.tsx`: 기존 대화·주문 동작을 유지하며 위 UI와 연결. 키·모델·TTS 설정은 계속 중앙 서버에 둔다.

## 검증

단위 검증은 텍스트 세션에서 가짜 듣기 상태를 만들지 않는지, 음성 대기와 실제 재생을 구분하는지, 무음·미래 재생 시각·끝난 재생에서 입을 닫는지를 확인한다. 브라우저는 캐릭터의 키오스크 내부 배치, 화면 변경 시 위치 이동, 결제 버튼과의 비겹침, ‘내 말’ 표시, 자막·기록 열기, 음소거·끼어들기·자연 종료, 동작 줄이기와 기존 주문·결제 회귀를 확인한다. 실제 매장 마이크/STT 및 실물 결제 시험과 구별한다.

2026-11-23 확인 결과: 웹 단위 테스트 42개, 아바타·안내·대화 결제 브라우저 21개, 기본 메뉴·주문·결제·자동 출력 브라우저 25개를 통과했다. 타입 검사와 별도 임시 경로의 웹 빌드도 통과했다. 데스크톱과 430px 화면의 실제 배치를 렌더링해 확인했다. 공개 AI 데모에서도 원본과 동일한 아틀라스 파일이 제공되고 실제 중앙 TTS 재생 중 입 열림·종료 후 닫힘·사용자 ‘안녕하세요’ 표시·사이드바 없음까지 확인했다. 실물 마이크·STT 연결 시험은 이번 범위가 아니다.
