# SWitch 주문 에이전트 설계

STT 이후의 텍스트를 받아 손님과 대화하고 주문 도구를 실행하는 에이전트를 개발한다. 주요 이용자는 노인과 아이이며, 필요한 내용을 기억하고 적절한 순간에 짧게 알려 주는 점원 경험을 목표로 한다. 마이크·STT·하드웨어·실제 결제는 범위에서 제외한다. 로컬 키오스크의 채팅 모달·텍스트 스트리밍·OpenAI 음성 안내를 테스트용으로 연결했다.

## 현재 구현 상태

2026년 11월 21일 기준. OpenAI Agents SDK 단일 주문 에이전트, 19개 도구, 한국어 응대 지침과 주문 검증·최종 확인 게이트를 구현했다. 기존 키오스크 위 채팅 모달에서 현재 장바구니를 공유하고 텍스트 스트리밍·OpenAI 음성·끼어들기를 시험할 수 있다. 주문 확인 화면부터 결제수단·리더기·완료 안내와 세션 종료까지 기존 데모 결제 흐름에 연결했다.

메뉴 112개에 상세 지식을 연결했다. 공식 음료 정보 411건에서 111개 메뉴 이름을 매칭했으며, 323개 온도·크기·디카페인 조합 중 322개 조합의 당류·카페인 수치를 공식 자료에서 확인했다. 나머지와 비공개 배합량은 데모 추정값으로 채우고 출처를 분리했다. 기본 답변은 짧게, 정확한 수치를 물을 때만 상세히 안내하도록 했다.

에이전트 자동 테스트 98개와 웹 단위 테스트 39개, 웹 빌드를 검증한다. 실제 GPT-6.2 Sol로 기본 주문 추가·수정과 스트리밍을 확인했으며 OpenAI Realtime 음성에서 24kHz 모노 오디오 생성도 확인했다. 이는 전체 시나리오의 품질 평가나 매장 실증 결과가 아니다.

세션 영속화, 실제 매장 재고·예약·결제와 직원 알림 시스템은 후속 연결 대상이다. 마이크 발화 시작 감지와 STT 자체는 계속 앞단의 책임이다.

## 근거 자료와 적용 순서

사용자의 이번 대화에서 정한 범위와 대화 정책을 우선한다. 기존 [진행 상태](../진행상태.md), [사업계획서 초안](../../references/downloads/33_SWitch_사업계획서%20초안_중간보고서-1.docx), [원페이퍼](../../output/onepaper_20261104/SWitch_원페이퍼_사업계획서.docx), 시장조사·비즈니스모델 발표 자료로 제품 배경을 확인했다. 예전 문서의 화면 인식·클릭 방식은 후속 어댑터 후보이며 현재 에이전트의 필수 전제로 삼지 않는다.

기존 메뉴 가격·온도·옵션은 시제품 자료다. 실제 매장 재고와 공식 판매 정책으로 취급하지 않는다. 영양·알레르기 지식은 별도 데이터의 공식값·추정값 표시를 따른다. 자료가 바뀌면 메뉴 복사본도 별도로 갱신해야 한다.
