# SWitch 주문 에이전트 설계

STT 이후의 텍스트를 받아 손님과 대화하고 주문 도구를 실행하는 에이전트를 개발한다. 주요 이용자는 노인과 아이이며, 필요한 내용을 기억하고 적절한 순간에 짧게 알려 주는 점원 경험을 목표로 한다. 마이크, STT, TTS, 하드웨어, 실제 UI 조작과 결제 처리는 이번 구현 범위에서 제외한다.

## 문서

- [OpenAI 구현 방식 비교](OpenAI_구현방식_비교.md): Agent Builder, Agents SDK, Responses API와 호스팅 Agents API 비교 및 선택 근거.
- [에이전트 설계](에이전트_설계.md): 대화 정책, 상태, 도구, 최종 확인, 중단 처리.
- [키오스크 API 요청 명세](키오스크_API_요청명세.md): 키오스크 팀이 제공해야 할 데이터와 동작 계약. 제안 상태이며 실제 제공 API가 아니다.
- [검증 시나리오](검증_시나리오.md): 자동 검증과 실제 모델 대화 평가의 구분.
- [실행 안내](../../order-agent/README.md): 로컬 텍스트 대화와 API 없는 가상 도구 시연.

## 현재 구현 상태

2026년 11월 20일 기준. Python OpenAI Agents SDK 기반 단일 주문 에이전트, 한국어 대화 지침, 13개 가상 도구, 기존 시제품 112개 메뉴의 독립 복사본, 주문 검증과 최종 확인 게이트를 구현했다. 기존 키오스크 UI는 수정하지 않았다.

SDK 실행기를 모형 모델로 구동하는 테스트를 포함해 자동 테스트 23개를 통과했다. 이는 자연어 이해 품질이나 실제 OpenAI 모델 대화 품질을 검증한 결과가 아니다. 현재 실행 환경의 키 제공 여부와 무관하게 이번 작업에서는 유료 모델 호출을 실행하지 않았다.

다음 단계는 모델 ID와 API 자격증명을 설정한 뒤 시나리오별 실제 대화 평가다. SDK 스트리밍, 발화 재생 완료 이벤트, 끼어들기 전송 계층, 재고 API와의 연동, 세션 영속화는 아직 구현하지 않았다. 완성 제품이 아닌 첫 검증용 구현이다.

## 근거 자료와 적용 순서

사용자의 이번 대화에서 정한 범위와 대화 정책을 우선한다. 기존 [진행 상태](../진행상태.md), [사업계획서 초안](../../references/downloads/33_SWitch_사업계획서%20초안_중간보고서-1.docx), [원페이퍼](../../output/onepaper_20261104/SWitch_원페이퍼_사업계획서.docx), 시장조사·비즈니스모델 발표 자료로 제품 배경을 확인했다. 예전 문서의 화면 인식·클릭 방식은 후속 어댑터 후보이며 현재 에이전트의 필수 전제로 삼지 않는다.

기존 메뉴 가격·온도·옵션은 시제품 자료다. 실제 매장 재고, 영양·알레르기 정보 또는 공식 판매 정책으로 취급하지 않는다. 자료가 바뀌면 메뉴 복사본도 별도로 갱신해야 한다.
