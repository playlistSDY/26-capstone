# 음성 입력 필터 시제품

2026-11-22. ESP32 수음 CLI에서 실험하는 독립 앞단이다. 에이전트와 결제 도구는 호출하지 않는다. `전달할 문장`은 연결 시 사용할 후보 이벤트이며 실제 주문 적용이 아니다.

## 역할을 분리한다

`USB PCM → DC 제거 → 로컬 Silero VAD + 배경 소음 추정 → STT 조각 → 발화 합치기 → 대상·완료 여부 판단 → 전달/무시/대기/확인 필요`

VAD가 맞혀야 하는 것은 사람 말소리 여부다. 목소리가 크거나 낮은 사람을 주문자로 고르지 않는다. 시니어·아이·작은 목소리·발화 거리에 따른 음량 차이 때문에 에너지 문턱만 높이는 방식은 사용하지 않는다. 여러 사람의 의논도 말소리이므로 VAD에서 제거할 대상으로 간주하지 않는다.

STT 뒤에서는 최근 점원의 질문, 순서가 있는 원문 조각, 세션 활성 상태를 읽어 키오스크에게 하는 요청인지 판단한다. 단일 마이크의 `speaker_identity`는 명시적으로 unknown이다. 화자 분리·방향 추정·거리를 측정한 것으로 꾸미지 않는다.

## 구현한 것

- Silero VAD 6.2.1 ONNX, CPU 스레드 하나. 48kHz 음성을 FIR 저역 통과 후 16kHz로 바꾸고 32ms마다 판단한다. 고정 커밋 모델·SHA-256·MIT 라이선스를 저장했다.
- 신경망이 비음성으로 확신한 구간에서 배경 RMS를 추정한다. 소음 상승·하강에 서로 다른 추종 속도를 적용하고 충격음 한 번으로 문턱이 크게 뛰는 것을 줄인다. 사용자의 발화를 배경 소음으로 학습하지 않는다.
- 보통 말소리 후보는 동적 에너지 문턱과 VAD를 같이 본다. VAD가 말소리로 강하게 판단한 경우는 낮은 에너지도 보존한다. 현재 수치는 초기 실험값이며 현장·화자별로 검증해야 한다.
- 288ms 사전 버퍼로 첫소리를 보존한다. 0.65초 무음은 STT 조각 경계이며 주문 완료가 아니다. 짧은 비음성 후보는 API 전송 전에 버린다.
- 조각 이후 1.4초 동안 추가 발화를 기다린다. 새 말이 시작되거나 STT가 진행 중이면 확정하지 않는다. 미완성 판단은 마지막 조각 뒤 최대 6초 대기한다. 텍스트를 임의로 고치지 않고 원문과 정정 표현을 순서대로 보존한다.
- 판단 중 새 말이 들어오면 revision이 달라진다. 늦은 accept를 폐기하고 전체를 다시 판단한다. USB 큰 누락·STT 실패·큐 초과는 남은 단어만으로 주문을 만들지 않는다.
- 완성된 문장을 전달한 뒤 한참 후 나온 말을 미리 예측해서 합칠 수는 없다. 완료 대기 시간보다 긴 멈춤은 새 턴일 수 있으며, 실제 에이전트 연결 시 이전 주문 문맥으로 정정해야 한다. `--join-wait`와 `--incomplete-wait`로 느린 발화를 비교한다.
- 대상이 불분명한 “네”는 바로 무시하지 않는다. 뒤에 말을 더 기다리되, 계속 대상이 불명확하면 조용히 종료한다. 동행자 대화마다 자동으로 질문하거나 주문 에이전트를 호출하지 않는다.

## 의미 판단 모델

기본 `--filter auto`는 `TYPESAFE_API_KEY`가 있으면 Jev, 없으면 기존 OpenAI 키로 `gpt-5.6-luna`를 사용한다. 주문 에이전트의 모델 설정은 바꾸지 않는다. OpenAI는 structured output으로 action/reason만 받으며 점수나 확률을 생성하게 하지 않는다. Jev는 대상과 발화 완료를 독립 Choice 질문으로 묻고 공식 응답의 확률·confidence를 확인한다.

Jev는 오디오 VAD를 대체하는 것으로 연결하지 않는다. STT 이후의 텍스트와 문맥을 판단하는 어댑터다. 현재 환경에는 Jev 키가 없어서 요청 스키마·응답 분기만 검증했고 실제 Jev 호출·한국어 정확도·국내 지연은 미검증이다. `--filter rules`는 보수적인 비교 기준이며 Jev와 같은 의미 판별 성능이라고 주장하지 않는다.

| 입력 예시 | 기대 분기 |
| --- | --- |
| “아이스…” → 잠시 후 “아메리카노…” → “한 잔 주세요” | 같은 턴으로 합친 뒤 전달 |
| “두 잔… 아니 한 잔 주세요” | 정정 원문을 보존한 한 턴 |
| “너 뭐 먹을래? 나는 라떼” | 동행자 의논으로 무시 |
| “네” + 직전 점원의 질문 있음 | 문맥에 맞는 짧은 대답이면 전달 |
| “네” + 질문·대상 정보 없음 | 기다린 뒤 대상 불명확이면 종료 |
| 의논과 요청이 뒤섞여 어느 부분이 주문인지 불명확 | 자동 전달 보류 |

STT는 외부 오디오 API, 의미 판단은 별도의 텍스트 API다. 필터 판단의 모델·토큰·응답 시간을 진단 이벤트에 기록한다. 로컬 VAD 자체에는 API 요금이 없다.

## 확인한 범위와 남은 평가

자동 테스트는 소음 문턱 추종·작은 음성 보존·짧은 후보 종료·느린 발화 합치기·정정·판단 도중 추가 발화·늦은 STT·큐 실패·대상 불명확 종료를 확인한다. 실제 OpenAI 의미 판단은 소규모 수기 사례 집합으로 별도 실행한다. 이를 일반 정확도로 환산하지 않는다.

`check_voice_noise.py`는 팬/백색/핑크 소음·충격음, 작은/보통 음량, 합성 음높이와 속도 변화, SNR 20/10/5/0/-5dB 혼합으로 반복한다. 음성 후보 검출을 측정하며 STT 내용의 정확도는 측정하지 않는다. 음높이·속도를 바꾼 합성 음성은 실제 시니어·아이 발화 검증의 대체물이 아니다.

실제 카페 현장 검증은 아직 하지 않았다. 다음 조건을 같은 발화로 반복하고, 일반 음량의 오탐과 작은 말의 누락을 함께 비교해야 한다.

| 축 | 비교 조건 |
| --- | --- |
| 실제 화자 | 낮고 높은 목소리, 작은 목소리, 시니어·아이의 실제 말투 |
| 거리 | 15/30/60cm, 마이크 정면과 옆쪽 |
| 소음 | 조용함, 음악, 커피 머신·그라인더, 손님 웅성거림, 순간 충격 |
| 말하기 | 한 번에 말하기, 중간 0.5/1/2/4초 쉬기, 망설임, 정정 |
| 여러 사람 | 한 사람이 주문, 두 사람이 의논, 다른 사람의 별도 주문, 겹쳐 말하기 |
| 시스템 음성 | TTS 꺼짐, TTS 재생, TTS와 고객 동시 발화 |

측정할 값은 비음성의 STT 전송 횟수, 실제 발화 누락, 문장 잘림/잘못 합침, 주변 의논의 잘못된 전달, 의미 필터 false accept/false reject, 마지막 발화부터 판단까지 p50/p95, 전체 API 비용이다. 소음 dBA나 SNR을 측정하지 않은 방을 ‘고소음 검증 완료’라고 표시하지 않는다.

현재는 AEC·화자 분리·발화 방향/거리 추정·실제 에이전트 세션 문맥 연결·TTS 자동 끼어들기가 없다. 특히 TTS 자기 음성과 주변 사람의 주문 문장은 VAD만으로 해결되지 않는다. 물리적인 마이크 배치와 재생 참조를 이용한 AEC, 실제 대화의 last_question 연결이 후속 작업이다.

## 실행과 근거

[마이크 실행 안내](../../hardware/kiosk_audio_monitor/README.md)의 STT 명령과 검증 스크립트를 사용한다. 원본 마이크 음성은 저장하지 않으며, 진단용 JSONL은 선택적으로 `tmp/`에 기록한다.

- [Silero VAD 공식 저장소](https://github.com/snakers4/silero-vad): 로컬 말소리 판별 모델.
- [TypeSafe 공식 문서](https://docs.typesafe.ai/introduction): 상태와 typed questions를 이용한 구조화 판단.
- [TypeSafe API 예제](https://docs.typesafe.ai/introduction/quickstart): Choice 요청·응답·확률·confidence 형식.
- [GPT-5.6 Luna 공식 문서](https://developers.openai.com/api/docs/models/gpt-5.6-luna): 비용을 고려한 의미 필터 후보.
