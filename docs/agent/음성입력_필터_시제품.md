# 음성 입력 필터 시제품

2026-11-22. ESP32 수음 CLI와 로컬 웹에서 실험하는 독립 입력 앞단이다. 중앙 주문 에이전트·주문 도구·결제는 호출하지 않는다. 말풍선은 에이전트에 전달할 입력 원문을 미리 보여 준다.

## 입력을 보존하는 역할 분리

`USB PCM → DC 제거 → 로컬 VAD·소음 추정 → STT → 발화 합치기와 대상 판별 병렬 처리 → 전달할 말`

VAD는 말소리 여부를 판단한다. 크기·음높이·나이·성별로 주문자를 고르지 않으며 동행자 의논도 음향적으로는 말소리다. 단일 마이크에서 speaker_identity는 unknown으로 기록한다.

STT 뒤의 필터는 메뉴 허용 목록이나 주문 문법 검사기가 아니다. 단어·단답·대명사·수량·정정·인사·불만·매장 문의·도움 요청·추천 요청을 모두 대화 입력으로 취급한다. “그거 말고 다른 걸로 주세요”, “해줘. 2개.”, “아니”, “아이스”, “라떼”, “잘 안 들려”, “화장실 어디예요?” 등을 원문 그대로 남긴다. 뜻과 참조를 해결하고 필요한 확인을 하는 것은 주문 에이전트 역할이다.

명백한 방송/자막 또는 확실히 다른 사람에게 하는 동행자끼리의 대화만 제외한다. 다른 사람 몫을 점원에게 주문하는 말은 제외하지 않는다. 대상이 애매하다는 이유만으로 정상 대화를 버리지 않고 문맥 해석 대상으로 넘긴다. 따라서 단일 마이크만으로 대상 오인을 완전히 없앨 수 있다는 보장은 없다.

## 음향 처리

- Silero VAD 6.2.1 ONNX, CPU 스레드 하나. 48kHz를 FIR 저역 통과 후 16kHz로 바꾸고 32ms마다 판단한다. 고정 커밋·해시·MIT 라이선스를 포함하며 실행 중 모델을 다운로드하지 않는다.
- 비음성으로 판단한 구간에서 배경 RMS를 추정하며 상승/하강 추종 속도를 다르게 적용한다. 충격음 한 번으로 문턱이 크게 뛰는 것을 제한한다.
- 실제 ESP가 큰 목소리에만 반응하던 문제를 수정했다. VAD 모델 입력만 기본 8배 보정하고 피크를 제한한다. 원본 PCM·RMS는 보존하며 에너지 문턱을 작은 음성의 절대 차단 조건으로 쓰지 않는다. 실제 입력 진단에서 보정 전/8배의 VAD 검출 프레임은 62/99개였고 사용자가 보통 목소리에서 반응함을 확인했다. 이는 일반 정확도 수치가 아니다.
- 288ms 사전 버퍼, 최근 4프레임 중 2개의 시작 증거를 사용한다. 기본 0.45초 무음은 STT 조각 경계이며 명령 완료가 아니다.

## 발화 합치기와 속도

추가 발화 확인 1초를 의미 판별과 병렬로 처리한다. STT가 나오면 바로 판단을 시작하고, 빨리 끝난 결과는 추가 발화 확인 창까지 보류한다. 새 말이 시작되거나 새 STT가 오면 revision이 달라져 이전 판단과 보류 결과를 폐기한다. 인식 원문과 정정 표현을 순서대로 보존한다.

명확한 단일 메뉴 직접 요청과 일부 짧은 대화는 로컬 빠른 경로를 사용한다. 패턴에 맞지 않는 말은 차단하지 않고 의미 모델로 판단한다. 미완성 접속사 등은 최대 6초 이어 듣되, 더 말하지 않으면 그 원문도 문맥 해석 대상으로 전달한다. 이미 전달한 말 뒤에 한참 후 나온 수량·정정은 새 턴일 수 있으며 실제 에이전트 연결 시 이전 대화/장바구니 문맥으로 이어야 한다. 다음 발화를 무한히 예측하여 합치지는 않는다.

이전 현장 로그에서 STT 이후 처리에 약 1.3~2.8초가 추가된 사례들이 있었다. 새 웹에서 사용자가 말한 단일 메뉴 요청 한 건은 STT 1.155초, 이후 0.035초, VAD 발화 끝부터 1.67초였고 사용자가 체감 속도 개선을 확인했다. 이 한 건을 모든 문장의 보장 지연으로 일반화하지 않는다. 의미 모델이 필요한 대화는 네트워크 시간이 더 든다.

USB 큰 누락·STT 실패·큐 초과는 남은 단어만으로 주문을 만들지 않는다. 필터 서비스 오류는 명시적으로 보류하며 자동 재시도하지 않는다. 최근 전달한 사용자 발화 4개의 짧은 문맥을 입력 판단에 보존하지만, 실제 에이전트의 응답/질문/장바구니 상태 연결은 아직 별도 통합이 필요하다.

## 모델과 비용

기본 auto는 TYPESAFE_API_KEY가 있으면 Jev, 없으면 기존 OpenAI 키로 gpt-5.6-luna를 사용한다. 주문 에이전트 모델은 바꾸지 않는다. OpenAI는 구조화된 분기만 받으며 확률을 만들어내게 하지 않는다. Jev는 대상/이어질 말 여부를 독립 Choice로 묻고, 다른 사람 대상임을 높은 확률과 confidence로 판단한 경우에만 제외한다. 뜻이 모호하거나 짧으면 에이전트의 문맥 해석 대상으로 둔다.

Jev는 음향 VAD를 대신하지 않는다. 현재 Jev 키가 없어 요청 스키마/응답 분기만 검증했으며 실제 호출·국내 지연·한국어 정확도는 미검증이다. STT 오디오 API와 의미 필터 텍스트 API는 별도 요금이다. 로컬 VAD·빠른 경로에는 추가 API 요금이 없다. rules는 비교용 기준이며 의미 모델과 같은 성능이라고 주장하지 않는다.

## 확인한 것과 남은 현장 평가

자동 테스트는 작은 음성 보존·문턱 추종·첫소리·끊어 말하기·정정·STT 대기·늦은 판단 폐기·단답/참조 보존·원문 전달·큐 실패를 확인한다. 실제 의미 모델에는 소규모 수기 대화 사례 집합을 별도로 실행하며 일반 정확도로 환산하지 않는다.

합성 음향 시험은 팬/백색/핑크 소음·충격음, 작은/보통 음량, 합성 음높이와 속도 변화, SNR 20/10/5/0/-5dB 혼합으로 반복한다. 입력 보정 수정 후 비음성 5조건의 후보는 0개였고 작은 음성·합성 음높이 변화·SNR 20~0dB에서 후보를 검출했으나 -5dB는 놓쳤다. 후보 검출 시험이며 STT 단어 정확도나 실제 시니어·아이·카페 환경의 검증을 대신하지 않는다.

실제 카페 현장 검증은 남아 있다. 화자/목소리/거리 15·30·60cm/정면·측면/음악·그라인더·웅성거림/0.5·1·2·4초 중간 멈춤/여러 사람 의논·겹침/TTS 재생 조건을 비교해야 한다. 누락·잘못 합침·주변 대화의 잘못된 전달·false accept/false reject·마지막 말부터 판단까지 p50/p95·전체 비용을 함께 측정한다.

AEC·화자 분리·발화 방향/거리 추정·실제 에이전트 세션 문맥·TTS 자동 끼어들기는 아직 없다. 설치 위치와 실제 재생 참조를 이용한 AEC가 후속 과제다.
