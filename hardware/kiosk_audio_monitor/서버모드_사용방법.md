# 구형 키오스크용 마이크·STT 테스트

## 웹에서 바로 연결

별도 음성 데모: https://temp.sdy.world/60df3fe1-a566-434c-8dcd-1ed75d82ded2/

전달받은 초대 링크로 데스크톱 Chrome·Edge에서 열고 상단 `마이크 연결` 설정을 연다.
처음 한 번 `ESP32 마이크 연결`을 누른다.
장치 선택창에서 ESP32의 `USB JTAG/serial debug unit`을 선택한다.
브라우저가 USB PCM을 보안 WebSocket(WSS)으로 보내며 설치형 프로그램은 필요 없다.
허용한 장치는 `다음부터 허용한 마이크 자동 연결`을 켜두면 새로고침 후에도
getPorts로 찾아 다시 연결한다. 브라우저가 USB 권한을 계속 보관하는 범위에서 동작한다.
접근 권한을 지우거나 승인 장치가 여러 대면 설정에서 다시 선택한다.
장치 설정은 모달에 있고 본문에는 아바타·말풍선·실제 이벤트 기반 진행 단계와
항상 펼쳐진 처리 기록이 나온다. 녹음은 파일로 저장하지 않는다.

상단 `음성 처리 일시정지 / 음성 처리 재개`는 USB 연결과 별개다.
일시정지 시 서버 세션을 종료하고 USB는 열어두되 읽은 소리를 전송·보관하지 않는다.
재개하면 새 서버 세션을 만들고 새 음성부터 처리한다. 중단 중의 말을 재생하지 않는다.
일시정지 설정도 새로고침 후 유지한다. `마이크 연결 해제`는 USB까지 닫는다.
접속 키는 링크의 fragment로 전달하고 즉시 주소창에서 지운다.
초대 인증 쿠키는 HttpOnly·Secure·SameSite=Strict이고 24시간 유지된다.
기기 서버용 키와 OpenAI 키는 브라우저 코드에 포함하지 않는다.

`Windows 연결 도우미 설치`는 설치형 화면을 원하는 경우의 선택 기능이다.
내려받은 `SWitch-Voice-Setup.cmd`를 10분 안에 실행하면 HTTPS로 패키지를
받고 SHA-256을 확인한 뒤 사용자 LocalAppData에 풀고 바탕화면 바로가기를 만든다.
관리자 권한, Python 수동 설치, 시스템 드라이버 교체는 수행하지 않는다.
설치가 끝나면 로컬 브라우저 테스트 화면이 열린다. ZIP 직접 내려받기도 지원한다.
웹 수음과 설치형 수음은 같은 USB 및 서버 슬롯을 동시에 사용할 수 없다.

실제 USB 드라이버가 없어서 COM 포트가 안 뜨는 경우에는 페이지의 Espressif
공식 드라이버 안내를 따른다. 연결 도우미는 OS의 USB 드라이버를 대체하지 않는다.

## 처리 위치

- ESP32: 기존 펌웨어로 ICS-43434 소리를 USB PCM으로 전송.
- Windows PC: USB 수신 → HTTPS 전송, 로컬 말풍선·로그 화면 표시.
- sdylab: CRC 검증, DC 보정, Silero VAD, 동적 문턱, 발화 합치기,
  OpenAI STT 및 의미 필터 요청, 최종 전달 후보 생성.
- OpenAI: 기존과 같은 STT와 필요한 의미 판단. API 키는 서버에만 보관.

PC에는 NumPy·ONNX Runtime·Silero·OpenAI SDK를 설치하지 않는다.
Python과 pySerial, 글꼴·인증서·화면 파일이 ZIP 안에 있다.
실제 주문 에이전트와 결제에는 아직 연결하지 않는 음성 입력 전용 테스트다.

## Windows에서 실행

1. ZIP을 완전히 풀고 폴더 전체를 키오스크로 복사한다.
2. ESP32를 USB 데이터 케이블로 연결한다. 기존 오디오 전송 펌웨어를 유지한다.
3. Arduino 시리얼 모니터와 다른 마이크 테스트를 닫는다.
4. `마이크_테스트.bat` 실행. 인터넷이 연결되어 있어야 한다.
5. 말풍선에는 에이전트에 넘길 문장, 오른쪽에는 실제 처리 로그가 나온다.
6. 화면에서 `수음 중지`로 멈추거나 `종료.bat`으로 이 테스트만 종료한다.

장치를 자동으로 찾지 못하면 `연결설정.json`의 `serial_port`를
장치 관리자에 표시된 번호(예: `COM3`)로 바꾼다. 빈 문자열은 ESP32 한 대 자동 검색.
`server_url`은 `/voice-api`까지 포함한 주소다.

`연결설정.json`에는 이 테스트 서버에 접속할 장치 전용 키가 있다.
OpenAI 키는 아니지만 서버 사용 권한이 있으므로 ZIP과 설정 파일을 공개하지 않는다.
기본 예제 설정으로 직접 빌드한 경우 실제 서버 주소·장치 키로 교체해야 한다.

## 네트워크 및 실패 처리

48kHz·16bit·모노 원음과 USB 패킷을 약 40ms마다 보낸다.
지속적인 업로드는 약 100KB/s(약 0.8Mbps + 전송 오버헤드)이다.
기본 모드에서는 서버로 주변 소리도 계속 전송하며 원음은 파일에 저장하지 않는다.
웹은 조각별 HTTP 응답을 기다리지 않는 지속 연결을 사용한다.
짧은 전송 정체는 순서대로 완충·전달하고, 누적 메모리는 약 300KB로 제한한다.
긴 정체·서버 끊김 때는 USB를 닫지 않고 해당 서버 세션만 종료하고 자동 재연결한다.
이때 이전 미완성 음성은 재전송하지 않고 화면에 다시 말해 달라고 안내한다.
이전 세션의 늦은 인식 결과는 버린다. 일시정지나 연결 해제를 하면 재연결도 취소한다.
설치형 Python 전달기는 기존 HTTP 경로를 유지하며 오류 시 다시 수음을 시작한다.
시험 서버는 동시 마이크 한 대만 허용한다. 다른 테스트가 사용 중이면 먼저 중지한다.

이번 구성은 PC의 추론 부담을 없애기 위한 것이다. 실제 J3710의 CPU 사용률,
브라우저 반응 속도, 매장 네트워크 지연과 소음 환경은 실물에서 별도 확인해야 한다.
오디오 전송과 웹 화면도 CPU를 사용하므로 부하가 0인 것은 아니다.
TTS 스피커 출력 중의 반향 제거(AEC)는 이 테스트에 추가하지 않았다.

## 개발·서버 운영

기존 Mac 로컬 모드: `마이크_웹.command` (기존 동작 유지).
서버 모드: `voice_dashboard.py --remote-config /절대경로/연결설정.json`.
서버: `voice_remote_server.py --port 18734`, HTTPS 프록시 뒤 loopback 전용.
웹 스트림 서버는 같은 프로세스에서 loopback 18736을 사용한다.
웹 서비스는 인증 쿠키·Origin을 검사한 뒤 loopback으로만 WebSocket을 전달한다.
서버 전용 `VOICE_REMOTE_TOKEN`(32자 이상)과 `OPENAI_API_KEY`가 필요하다.
배포 서비스 원본은 `switch-voice-server.service`이며 다른 에이전트와 별도 실행한다.
서버 Python 의존성은 `requirements-stt.txt`, 모델은 `models/`를 사용한다.
원본 코드를 옮길 때는 루트 기준 hardware 폴더와 인증서 경로를 유지한다.

재생성: `build_windows_voice.py --config /비공개/연결설정.json`.
생성 위치: `output/windows/SWitch-Voice-ThinClient.zip`.

웹 서비스는 같은 소스의 `voice_demo_server.py`, `switch-voice-demo.service`로 실행한다.
`VOICE_DEMO_ACCESS`와 `VOICE_DEMO_URL`은 서버의 별도 demo.env에 보관한다.
배포 ZIP은 서비스의 downloads 폴더에만 두며 Git에 추가하지 않는다.
다운로드는 초대 인증 또는 설치 파일에 발급된 10분 만료 서명으로 보호한다.

  가상 시리얼 수신, 초대 인증, 다운로드 서명·무결성, WebSocket 인증·바이너리 전달.
- Node 3개: 정체 시 음성 순서·바이트 보존, 과도한 적체 복구·이전 결과 무시,
  중지 시 자동 재연결·버퍼 취소.
- 브라우저 모의 USB + 실제 WebSocket/작업 프로세스: 실제 ESP 전송량 수준,
  메시지별 1.1초 지연, 강제 서버 끊김 자동 복구, USB 유지, 새로고침 자동 연결,
  일시정지 중 전송 없음·재개, 모달·항상 열린 로그·진행 단계, 화면 1440/1024/390.
- 공개 HTTPS 웹 + 합성 USB 음성 + 실제 STT: “아이스 아메리카노 한 잔 주세요.”
  최신 WSS 인식, 서버 확정 약 1.63초, 일시정지 후 서버 해제·USB 유지,
  브라우저·API 오류 없음. 합성 재생 수치이며 실물 키오스크 지연 보장은 아니다.
- 실제 Windows 설치 도우미 실행, J3710 CPU/지연 및 실물 ESP32의 Web Serial
  권한 선택은 아직 미검증. Mac에 ESP32가 연결되지 않아 이번 실물 시험은 하지 못했다.
