# SWitch 텍스트 주문 에이전트

앞단에서 STT가 끝난 텍스트로 점원처럼 대화하는 첫 프로토타입이다. OpenAI Agents SDK를 사용하며 키오스크의 상시 채팅 패널에 연결했다. 실제 매장 재고·결제·직원 호출에는 연결하지 않았다. 설계와 키오스크 API 요청 사항은 [설계 문서](../docs/agent/README.md)를 참고한다.

## 중앙 서버로 사용

[온라인 AI 키오스크](https://temp.sdy.world/980d563c-35d0-4ee2-9de0-161a08901e29/)와 로컬 키오스크는 기본적으로 sdylab의 에이전트 서버를 경유한다. 개별 키오스크에 API 키를 등록할 필요가 없다. 키·모델·음성 설정은 sdylab의 /home/sdy/.config/switch-agent/agent.env 한 곳에서 관리한다. [통합 운영 문서](../docs/agent/sdylab_통합운영.md)를 참고한다.

## 로컬 진단용 설치와 실행

Python 3.11 이상을 사용한다. 이번 검증 환경은 Python 3.14다.

```sh
cd order-agent
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

모델 ID와 키를 서버의 환경변수로 설정한 뒤 실행한다. API 키를 소스 파일에 저장하지 않는다. 모델은 함수 호출과 Responses API를 지원해야 한다.

```sh
export OPENAI_MODEL='사용할-모델-ID'
# OPENAI_API_KEY는 비밀 관리 도구나 현재 셸 환경에서 설정
.venv/bin/python -m switch_agent
```

`/state`는 실제 가상 장바구니 조회, `/quit`는 종료다. 각 실행은 독립적인 메모리 세션이며 종료하면 주문과 대화가 사라진다. 실제 모델 대화에는 OpenAI API 사용 비용이 발생한다. 기본 주문·수정의 실제 모델 스모크 테스트를 수행했다. 전체 대화 평가와 구분한다.

## 키 없이 실행

```sh
.venv/bin/python -m switch_agent --demo
.venv/bin/python -m unittest discover -s tests -v
```

`--demo`는 정해진 주문 도구 순서로 라떼 두 잔 중 한 잔만 차갑게 바꾸고 확인 후 가상 결제 진입 이벤트를 만드는 시연이다. 자연어 해석 시연이 아니다. 자동 테스트의 SDK 모델도 고정된 응답을 사용한다.

## 구현 파일

- `switch_agent/prompt.txt`: 짧은 진행 안내, 기억 도움, 필요한 질문, 추천과 마무리 정책.
- `switch_agent/domain.py`: 주문 상태, 옵션·수량·재고 검증, 최종 확인 게이트.
- `switch_agent/tools.py`: 20개 모델 도구와 가상 어댑터.
- `switch_agent/runtime.py`: 단일 세션의 SDK 실행과 대화 이력.
- `data/catalog.json`: 기존 키오스크 시제품 112개 메뉴의 메타데이터 복사본. 실제 매장 정보와 자동 동기화되지 않음.

가격·옵션 추가 금액은 기존 시제품 기준이다. 실제 재고 수량은 기본 null이며 soldOut만 카탈로그에서 읽는다. 테스트에서만 가상 재고 수량을 주입한다. 원재료·영양·알레르기 정보는 data/menu-knowledge.json에서 제공하며 공식값과 데모 추정값을 구분한다.

## 현재 한계

CLI는 완성된 텍스트를 반환한다. 웹 모달은 텍스트 스트리밍·OpenAI 음성·중단 전송을 지원한다. 미확정 추가는 서버 item_drafts에 기억하고, 동의 표현은 제한된 명확한 문구만 코드가 허용한다. 시나리오별 모델 평가와 세션 영속화가 다음 과제다. CLI는 텍스트 반환을 전달로 간주한다. 웹 모달은 음성 전체 재생 완료 후 서버에 전달을 확인하며 중간에 끊긴 요약은 무효화한다.

실제 배포에서는 환경변수 키를 신뢰된 백엔드에서만 사용하고, 세션 인증·지속 저장·이벤트 중복 방지·버전 충돌·quote와 재고 예약을 구현해야 한다. 현재 도구의 가상 결과를 실제 주문 접수·결제 완료·직원 알림으로 표시하지 않는다.

## 키오스크 모달로 테스트

1. `.env.example`을 `.env`로 복사하고 키를 넣는다. 대화 모델 기본 예시는 `gpt-6.2-sol`, 음성 모델은 `gpt-realtime-2.1-mini`, 음색은 `cedar`이다. `.env`는 Git에서 제외한다.
2. `에이전트_서버.command`를 실행하거나 `.venv/bin/python -m switch_agent.web`으로 서버를 켠다. 기본 주소는 127.0.0.1:18732다.
3. 별도 터미널에서 `kiosk-web`의 `npm run dev`를 실행하고 [키오스크](http://127.0.0.1:5173/)의 ‘주문 대화 테스트’를 누른다.
4. 새 메시지를 보내거나 ‘말 끊기’를 누르면 생성과 음성을 중단한다. 음성을 끄면 텍스트만 사용한다.

설정을 바꾼 뒤에는 에이전트 서버를 재시작하고 모달의 ‘다시 연결’, ‘새 대화’를 누른다. 키오스크 장바구니는 유지하고 새 대화가 현재 주문을 가져온다. API 키를 채팅창에 보내지 않는다. 자세한 이벤트 계약은 [채팅과 음성 테스트](../docs/agent/채팅과_음성_테스트.md)를 참고한다.


웹에서는 주문 종료 의도 → 주문 확인 화면 → 새 답변으로 동의 → 결제수단 선택 → 기존 리더기 → 완료/실패 안내까지 연결했다. 재시도·수단 변경·승인 전 취소는 대화로 요청할 수 있다. 완료 결과는 기존 데모 키오스크에서 받고, 완료 안내 후 대화 세션을 종료한다. 실제 카드 청구·PG 승인은 별도다. 자세한 내용은 [결제 연결과 검증](../docs/agent/결제_연결과_검증.md)을 참고한다.
